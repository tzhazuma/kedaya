# 可达鸭小程序 UI 规范

基础控件固定使用 Taroify，图标使用 Taroify Icons，业务页面通过 Kdy 组件复用品牌样式。
ESLint 会阻止在 presentation 层直接引入 Taro 原始表单控件和其他常见 UI 库。
主题入口为 `apps/miniapp/src/presentation/theme/appearance.scss`，从共享设计令牌映射小程序变量。
共享品牌色保持不变，Web 主题不随本端调整。

## 视觉

- 视觉语言是「**校园贴纸簿**」（Campus Sticker Book，规格与设计稿在
  `docs/design/campus-play/`），取自 `feature/pingdan` 分支的统一 UI：
  **真白底 + 墨蓝黑字 + 鸭黄主操作 + 淡粉/淡绿功能卡 + 手绘胶囊导航**。
  主色可达鸭黄，黄色按钮使用深色文字（黄底白字在真机阳光下看不清）。
- 页面左右留白 20px，卡片间距 12px，正文 14–16px。
- 375px 为设计基准；Taro 将 CSS px 转换为 rpx，避免把现有令牌错误地缩小一半。
  ⚠️ 从设计稿（或 `feature/pingdan`，那是 **750rpx** 基准）搬运数字时**一律除以 2** ——
  直接把 `80rpx` 写成 `80px` 在真机上是两倍大（入口页/首页的标题踩过一次）。
- **圆角只有三档**：卡片 / 宫格 / 浮层 24px（`$kdy-radius-2xl`），主视觉容器
  （首页功能卡、入口横卡、汇总块）30px（`$kdy-radius-3xl`），胶囊 999px。
  贴纸簿的"卡"是**圆角矩形**，不是玻璃胶囊。
  ⚠️ 前两档是**四个角不一致**的手绘圆角（多值，例如 `24px 20px 23px 21px`），
  对应设计稿的"轻微不规则的细描边"：整站的卡通感有一半来自这里。
  它们**只能整体用于 `border-radius`**；要单独改某一个角（气泡尾巴等）用
  `$kdy-radius-2xl-flat` / `$kdy-radius-3xl-flat` 标量 —— 把多值塞进
  `border-top-left-radius` 是非法值，整条声明会被编译器丢掉（静默失效）。
- **页面与卡片都是白的**：`.kdy-page` 是纯白（`$kdy-color-campus-white`），只在顶部
  留一层极淡的鸭黄环境光（`$kdy-gradient-aurora`，200px 内衰减到 0，长列表滚动时是纯白）。
  卡与页面靠一圈**手绘墨色轮廓**（`$kdy-border-sticker` = `2px solid rgba(ink,.10)`）
  分开，而不是靠灰底 —— 白底上的半透明白只会发灰。
  ⚠️ 只有**卡片 / 面 / 气泡**的定形描边才是 2px 墨色；**列表行之间的分隔线**
  （`border-bottom` 那一类）仍然是 1px `$kdy-tone-border`，不然一屏全是粗线。
- **尺寸 / 效果档位**（圆角、描边、阴影、渐变、淡色面）定义在
  `presentation/theme/tokens.scss` 的派生层，色相一律 `rgba($kdy-color-*)` /
  `color.mix()` 取自原子令牌，**没有手写色值**。它们刻意**不进**
  `packages/design-tokens/tokens.json`：那是四端共享的语义令牌，圆角与阴影是各端的
  视觉语言，塞进去会让"Web 改一张卡"变成"小程序跟着变"。
  （唯一的例外是新增的 `colorCampus` / `colorNight` **取色分组** —— 它们是色相本身，
  跨端可复用。）
- **淡色面是"功能卡"的专利**：四档 `$kdy-tone-pink`（社交 / 一起做点什么）/
  `$kdy-tone-mint`（校园自然）/ `$kdy-tone-yellow`（主操作）/ `$kdy-tone-milk`（中性），
  对应全局类 `.kdy-tone--pink|--mint|--yellow|--milk`。**一整块色面**只用于首页 /
  入口页那种"一眼看去是什么"的功能卡；正文区永远白底。淡面上**只用墨色字**。
- **渐变只剩一处**：`$kdy-gradient-brand` 现在是**实心鸭黄**（`campus.yellow →
  brand`，两端都是令牌色），用于主按钮 / 选中胶囊 / 悬浮球 —— 视觉上就是一块贴纸。
  渐变面上文字一律墨色；压在色面上的状态标签用 `.kdy-pill`（白底 + 细描边）。
- **阴影只负责"托一下"**：白卡 + 1px 描边已经分层，普通卡片用 `$kdy-shadow-card`
  （`0 4px 14px` 5% 墨色），浮层 / 手绘导航用 `$kdy-shadow-float`；
  淡色功能卡**不加投影**（两列并排时投影会在中间显出一条灰缝），靠色面本身分层。
  按下用 `scale(0.97)` 或换成奶白面，而不是变淡（变淡会和"禁用"长得一样）。
- **磨砂（`backdrop-filter`）只保留给 agent 页的 sticky 头部 / 输入区 / 悬浮球**。
  贴纸簿没有玻璃卡片：列表里的十几张白卡一律不加 blur（滚动会掉帧）。
- **页头固定带一只可达鸭**：模块页的页头由 `KdyHeading` 渲染，标题右侧挂
  `assets/campus/duck.png`（46px、`rotate(-7deg)`、`aria-hidden`、`pointer-events:none`）。
  它让每一页看起来都是"贴纸册的一页"；页面不要再自己写一套标题
  （会没有鸭子、字级也会打架）。
  ⚠️ 小程序端目前**没有 CSS 变量主题层**，所以深色模式还没落地 ——
  `tokens.json` 的 `colorNight` 与 `CampusThemeToggle` 已备好，
  但要先把页面 / 组件 scss 里的 `rgba($kdy-*, x)` / `color.mix()` 迁到 `var(--kdy-*)`
  才能接上（Sass 函数不接受 `var()`）。在那之前不要把主题开关接到页面上。
- 图标统一线性风格，品牌形象可使用原创资源；不混用多套图标。emoji **不再**充当吉祥物：吉祥物是固定贴图
  `assets/mascot/duck.png`（`presentation/theme/mascot.ts` 的 `DUCK_MASCOT_SRC`，经 `KdyMascot` 使用），
  因为 emoji 在不同微信版本 / 机型上渲染成各家自己的字形，34px 的头像里几乎认不出是鸭子，颜色也不受控。
  贴图是黄色鸭子，**不要**垫在品牌黄渐变上（糊成一片），要么直接放白底，要么用 `KdyMascot` 的 `plate`（白色圆盘底）。
  模块图标走 `.kdy-module-icon` + `KdyModuleIcon`：52px、圆角 22px、字形 26px 且
  `line-height: 1`（图标是**字体字形**，不锁行高会被 page 的 1.5 撑高、和旁边的图标对不齐）。
- **宫格图标是"淡色贴纸 + 墨色字形"**：一块淡色面 + 手绘墨色轮廓 + 墨色字形，
  平的、不渐变（贴纸是平的；一屏宫格挂投影会脏）。字形一律墨色 ——
  淡底上放彩色字形（尤其黄底彩字）在真机阳光下糊成一片。
  一档色相 = 一个使用场景：

  | tone | 色相 | 用在哪 |
  | --- | --- | --- |
  | `brand` | 品牌黄 | 常去的地方：凑凑、拼单、食堂 |
  | `success` | 绿 | 好结果 / 生活服务：跳蚤、失物招领、野生动物 |
  | `info` | 蓝 | 校园事务：课表、校园卡、场馆 |
  | `warning` | 橙 | 需要跑腿 / 代办：跑腿、偷外卖、技术服务 |
  | `danger` | 玫红 | 需要照顾的敏感模块：心理支持、宿舍矛盾、AI 画像 |
  | `neutral` | 灰蓝 | 账号与工具：通知、FAQ、身份、我的 |

  映射表在 `presentation/components/KdyModuleIcon/index.tsx` 的 `MODULE_TONES`
  （**仅视觉**，不影响任何功能与文案）；没登记的 id 落到 `neutral` + 通用图标，不报错。
  同一个图标集里优先用同一套线框变体（`-Outlined`），实心与线框混排会看起来"一大一小"。
- **选中态靠"材质"而不是"深浅"**：`KdyChip` 未选中是白底 + 校园描边，选中是
  **鸭黄实心 + 墨色字**。一屏十几个筛选胶囊时，浅黄底 + 黄描边只有一点点差别，
  用户得凑近看才分得清哪个在看 —— 差的是材质（白面 vs 实心黄面），不是深浅。
- **表单控件是"奶白实心面"而不是"白底细线框"**：`KdyField` 的控件框用
  `$kdy-tone-milk` 底 + 16px 圆角，出错时才出现危险色描边。卡片本身已经是白的，
  再画一层白底 + 灰描边的输入框会让整页变成"白里透白 + 一堆细线"。
- 深色胶囊（`.kdy-pill--dark`）只放**状态**（在线 / 计数），不放操作 ——
  它是这套暖白体系里唯一的重色块，用来让状态一眼可扫；操作永远是黄色的。
- 主次按钮、标签、加载、空态与进度使用统一封装；新表单、弹层、选择器直接优先选 Taroify。

## 文案

写法直接决定这页看起来像产品还是像脚手架：

- 只在**能帮用户做决定**时写说明（发布门槛、可见范围、数据时间、演示数据）。
  不写诗化装饰句、不复述标题、不为了"每页都有一行小字"凑字数。
- 免责声明与合规要点用短句（`第三方非官方平台 · 与上海科技大学官方系统无关。`），
  内容可以保留，语气不要像法务模板。
- 不把开发者词汇暴露给用户：模型名、`degraded`/`usedModel`、契约条款号、内部枚举。
  agent 页只在模型不可用时标一个「基础回答」。

## 标准件

新增页面前先找可复用的 Kdy 组件，不要另起一套基础控件：

| 组件 | 用途 |
| --- | --- |
| `KdyButton` | 主/次/幽灵/危险按钮，`block` 撑满，`loading` 表示提交中；`openType` 可透传 `share` / `chooseAvatar` |
| `KdyAvatar` | 头像展示（无图回退可达鸭贴图）；**选择**头像由页面上的 `KdyButton openType='chooseAvatar'` 触发 |
| `KdyMascot` | 吉祥物贴图（`size` / `plate` 白底圆盘）；agent 头像、悬浮球、登录注册卡都用它，不要再写 emoji |
| `KdyCard` | 内容卡片容器（`title` / `extra` / `onClick`） |
| `KdyField` | **表单唯一入口**（Taroify Field + Input 薄封装，支持 `type`（含 `nickname`）/ `maxLength` / `hint`） |
| `KdyChip` | 可点击胶囊：筛选器与单选（分类、成色、状态、排序）都用它 |
| `KdyTag` | 状态标签，`tone` 取语义色，不要自己写色值 |
| `KdyEmpty` | `loading / empty / error` 三态占位，可带行动按钮（重试、去发布） |
| `KdyHeading` | 页面标题区（`title` 必填，`subtitle` 可选、只在能帮用户做决定时才写） |

列表页与详情页的状态机统一走 `application/common/{listUseCase,detailUseCase}.ts`：
`hydrate()` 同步出缓存、`load()` 后台刷新、失败静默降级。页面只读 `useStore(...)` 的快照，
不要自己写 loading 布尔值。

`domain` 与 `application` 层禁止 import `data/**` 或 `@tarojs/*`（ESLint 强制），
平台能力一律经 `src/platform/**` 适配层。

## 页面与交互

首页是**用户自己挑的几个服务**，不是模块目录：

- 首屏是 **Hero**：`10月18日 周日` + `你好，昵称` + 一枚「编辑首页」玻璃胶囊，
  品牌渐变 + 同色光晕。它是整页唯一的重色块，回答的是"我到了哪"——
  首页原来第一眼是一行灰字加一张白卡片，看不出这是自己的首页，下面的宫格也没有对比参照。
  「编辑首页」放在 Hero 里（宫格卡片头不再挂"编辑"，避免同一个动作出现两次）。
- 「我的常用」宫格由**用户偏好**驱动（`application/homeLayout/`，
  缓存键 `StorageKeys.homeLayout` 拼登录用户，换号换一份），默认 9 个、上限 12 个，
  最后一格固定是「全部服务」；格子上不挂任何角标 ——
  没做出来的模块点开时给一句说明，不做成小字提前挂在首页上；
- 两个 `locked` 入口：`cou`（凑凑：拼单 + 找搭子，产品要求的一级入口）与
  `wellbeing`（心理支持，安全出口）。两者都可排序、**不可移除**，
  管理页会明说这条规则而不是让按钮静默失灵。契约里 `groupbuy` / `buddy`
  仍是两个独立模块，聚合关系只声明在 `domain/models/homeEntries.ts`（入口目录），
  不污染契约；
- 宫格下方是常驻的**安全出口**（心理支持 · 24 小时热线 12356），
  它不属于可自定义的内容，是 `wellbeing` 之外的**第二重兜底**；
- 「全部服务」落到**服务大厅**（`presentation/pages/home/services/`）：
  按使用场景分组（校园日常 / 交流与互助 / 关怀与成长 / 账号与身份 / 尚未上线）+ 搜索，
  未实现的模块（当前是 `facility`）列在「尚未上线」一组里，点它得到一句说明而不是白屏；
- 「我的 → 首页管理」（`presentation/pages/profile/home/`）增删与排序。
  用上移 / 下移而不是长按拖拽：小程序里跨行拖拽在真机上会飘，且读屏用户用不了。

服务入口来自共享模块契约；未实现模块明确提示，不能伪造数据或可用状态。
模块 id → 页面路径的唯一映射是 `app/routes.ts` 的 `MODULE_ENTRY_PATHS`（模块入口）
与 `homeEntryPath()`（含聚合入口），新增模块时同时登记路由与页面清单 ——
`app/__tests__/routes.test.ts` 会把「入口目录 / 路由表 / app.config.ts」三方锁在一起。

账号：登录 / 注册 / 找回密码 / 修改密码 / 绑定邮箱五页共用 `auth/auth.scss` 与 `KdyField`；
表单错误在字段下方即时提示，提交失败用后端返回的文案。

**登录页是产品门面，不出现任何演示账号 / 演示模式的字样。** Mock 凭据只放在开发用的
折叠面板（「发现 → 演示与调试工具」，见 `KdyDemoTools`）与 `docs/local-development.md`；
提审时给审核员的测试账号写在提审备注里（`docs/review-checklist.md` §6.1），
不印在页面上。

微信快捷登录是**第一级身份层的第三条入口**，与邮箱密码对等：

- 登录页与注册页共用 `presentation/hooks/useWechatAuth.ts` 这段编排
  （取凭证 → 调用例 → 回原页），不要各写一份；两页的首屏都是"一键登录 / 注册"
  的主视觉卡（`.kdy-auth__quick-card`），邮箱表单退到「或使用邮箱密码」之后 ——
  小程序里大多数用户只有这一种可用登录方式，先摆三个输入框会让人以为必须先注册邮箱。
- **一键登录就是一步**：`isNewUser` 为 true 时**不跳转**任何页面，建号即登录，
  直接回到用户原来要去的地方。昵称与头像随时可在「我的 → 编辑资料」里补 ——
  它们本来就必须由用户主动点（微信不给自动昵称），属于"可以后补"的动作，
  不该挡在登录中间。
- 微信侧的硬约束决定了表单写法：昵称必须用 `KdyField type='nickname'`
  （键盘给「使用微信昵称」），头像必须由用户点 `KdyButton openType='chooseAvatar'` 触发，
  回调给的是临时文件路径，须经 `platform/avatarPicker.ts` 压成 ≤64KB data URL 才能落库。
- 「我的」页是**目的地**而不是内容页：身份卡（品牌渐变 + 头像 + 昵称 + 一行账号/绑定状态，
  点进去就是编辑资料；形状与首页 Hero 同一套语言）→ 常用功能 4 列宫格（我的拼单 / 课表 /
  校园卡 / 身份绑定 / 首页管理 / 服务大厅 / 隐私与数据 / 常见问题）→ 账号与安全
  （动作按钮 + 状态标签）→ 关于（用户协议 / 隐私政策）。合规要点不在这一页复述，
  各自的主页才是权威位置。
- 「我的」页展示账号方式概览（邮箱 / 微信 / 校园系统）与对应动作；只剩一种登录方式时
  解绑按钮禁用并说明原因（后端也会拦），不要把「至少保留一种登录方式」写成前端独有规则。
- 开发模式下微信身份是本地模拟的（`simulated: true`），界面必须如实标注，不能冒充真实微信身份。

业务模块（跳蚤 / 跑腿 / 找搭子 / 失物招领 / 论坛）统一为「列表 → 发布 → 详情」三页：

- 列表页：关键词 + 筛选胶囊 + 触底加载更多 + 悬浮发布按钮（悬浮按钮必须叠加
  `env(safe-area-inset-bottom)`）；空态给出下一步动作而不是只写一句「暂无数据」。
- 详情页：只渲染领域函数允许的动作（`availableActions` 之类），
  未登录时引导登录，不发送注定 401 的请求；破坏性操作前二次确认。
- 发布页：客户端校验与服务端同规则，提交按钮在未通过校验时禁用并说明原因。

#### 列表卡片按模块**定制**，不做通用模板

「列表 → 发布 → 详情」是**流程**统一，不是**卡片**统一。每个模块的卡片要按该模块
用户真正要判断的事排信息顺序；把别的模块的卡片复制过来（改几个字段）就会退回
「所有模块长得一样」的状态。已落地的九种：

| 模块 | 卡片的形状 | 为什么 |
| --- | --- | --- |
| 跳蚤市场 | **双列商品网格**：图片占满格子 + 图上角标（分类 / 已预定 / 已售）+ 大字价格 | 二手交易先看图再看价；一行一卡会把图压成缩略图 |
| 跑腿 | 两条**站点导轨**（取 → 送）+ 大字赏金 + 截止时间（临期高亮 / 过期划线） | 值不值得跑、顺不顺路、来不来得及 |
| 失物招领 | 顶部「寻物 / 招领」两段式 + 卡片类型色带 + **地点 / 时间**两列对齐 | 匹配物品靠的就是这两条线索 |
| 拼单 | 进度为主角：「已拼 6 / 10 份」+ 进度条 + 「还差 4 份」 | 拼单的用户问题是还差几人、什么时候截止 |
| 食堂 | 热量大字 + **三条营养比例条**（蛋白 / 脂肪 / 碳水） | 「蛋白 32g · 脂肪 28g · 碳水 96g」没人会读 |
| 找搭子 | 活动 / 时间 / 地点事实区 + **名额条** + 标签与门槛 | 邀约的核心是时间地点、还剩几位、有没有门槛 |
| 论坛 | 主题行 + 右侧**热度统计簇**（回复 / 赞 / 时间），摘要固定两行 | 论坛扫的是"这帖有没有人理" |
| 偷外卖 | **三段状态轨**（记录 → 升级 → 解决）+ 订单号后四位 + 「仅你自己可见」 | 本人看的是"我这单走到哪一步" |
| 动物轨迹 | 地图 + 可信度条 + 免责说明 | 数据是推断的，可信度必须与结论一起出现 |

三条共用的硬约束（都属于「不属于某个模块的通用规则」）：

- **派生字段一律来自 `domain/models/*`**，页面不解析展示字符串（`routeLabel.split('→')`、
  `statusLabel === '寻物'` 这类写法都会在文案改动时**静默**失效）。为此各模块摘要
  补了 `fromPlace/toPlace`、`kind`、`deadlineUrgent/deadlinePassed`、`fillPercent`、
  `macroShares` 等字段，并都有单测。
- **进度 / 比例条统一用 `KdyProgress`**（Taroify `Progress` 的令牌化封装）：夹紧 0–100
  与取整只在一处做，页面不各写一遍宽度计算。
- **没有数据就不画**：没有缩略图时退化成文字徽标，不编一张假图；金额、人数、
  可信度这类数字宁可少显示一个也不要算错。

宿舍矛盾是匿名模块：进入前必须有二次同意门（同意记录落 `StorageKeys.consent`），
查看进度凭本地保存的追踪码，页面要说明「追踪码丢失后无法找回」，
并给出「紧急情况请直接联系辅导员 / 校园安保」的提示。

### 四个核心模块（身份 / 课表 / 校园卡 / 我的）

这四页共同的写法是**同一套状态机**：`hydrate()` 先同步读缓存让页面立刻有内容，
`load()` 再后台刷新，失败**保留旧数据**并标注时间与原因（见
`application/campus/campusUseCases.ts`）。落到界面上有三条硬规矩：

- **绝不显示假数据**：上游不可用时显示"上一次成功同步的数据 + 时间"（校园卡页把
  数据时间与上游状态标在余额旁边），而不是 `¥0.00` 或空列表；演示数据一律标「演示数据」。
- **失败不留死路**：区分「没绑定校园系统」（给"去绑定"）与「网络坏了」（给"重试"），
  绑定/解绑失败不改变已有状态，实名解绑后立即清掉明文视图。
- **写操作不乐观更新**（隐私开关与同意）：等后端确认后再改本地状态，
  期间显示「保存中…」，失败保持原状并明确报错 —— "以为关掉了其实没关"不可接受。

身份页：四个校园系统各自的「已绑定 / 未绑定 / 已过期」+ 绑它有什么用 + 一键绑定/解绑；
实名默认打码，展开明文是用户主动动作并会写审计（页面先告知）。解绑后对应数据立即不可读。

课表页：顺序是「今天（正在上 / 下一节还有多久 / 今天还剩几节）→ 本周 → 同步与手动加课」，
即按用户当下最急的问题排，而不是按数据表结构。时间文案全部用服务端算好的值，
客户端不重复实现"第几节是几点"。冲突由服务端给出，页面只提示。

校园卡页：主数字是余额（全页唯一使用 `$kdy-font-size-display` 的地方，放在一块
品牌渐变的"余额块"里；余额偏低 / 演示数据用玻璃胶囊标注，不用语义色标签 —— 低透明度
的橙/灰标签压在黄底上会发脏），
然后是「还能撑几天 / 今天花了多少 / 异常扣款 / 消费集中在哪」，流水放最后。
挂失给的是**可执行指引**（步骤 + 渠道），可达鸭对校园卡系统没有写权限，不谎称已挂失。

「我的」页的「隐私与数据」二级页承载契约 §9 的三项权利：开关、同意（可撤回、
能看出哪些还没授权）、数据导出；开关是自绘的纯 `View` 开关（Taroify 没有 Switch，
原生 `Switch` 两端表现不一致），色值取令牌。

### 可达鸭的全局入口

`KdyAgentFab` 是可达鸭的悬浮入口，挂在**四个 tabBar 页**（首页 / 发现 / 消息 / 我的）
与四个核心模块页上；点击是**带上下文跳转**（`module` / `page` 参数）而不是就地弹窗，
agent 一打开就知道用户在哪个页面，首屏直接给出这一页能问什么。

为什么不挂到每个页面：一是会与业务页自己的底部操作栏 / 悬浮发布按钮抢位置，
二是 Taro 没有全局布局层，硬做"全局注入"要引入事件总线，出问题难定位。
tabBar 页随处可达，用户到可达鸭**最多两步**，已经满足"全局可用"。
业务页需要时显式引入本组件并传 `raised` 避开底部操作栏。

agent 页的界面约定：

- **气泡分左右两栏**：用户侧品牌渐变 + 墨色字，助手侧玻璃底 + 头像；
  两者靠"尖端那个角收小"表达是谁在说（只靠左右对齐的话，长回答看起来像页面公告）。
- **`answer` 逐行渲染**（不依赖 `<Text>` 对 `\n` 的处理）。
- **正文只负责"说人话"，`steps` / `sources` / `facts` 收进可展开的「思考过程」**：
  折叠时给一行摘要（查了几项数据 / 几条事实 / 参考几条知识），展开后逐条列出
  "查了什么、查到什么、依据是什么"。模型组织的话本来就会把事实说一遍，再把 facts 原样
  铺在下面，同一句话就在一个气泡里出现两次 —— 看起来像复读。数据必须"随时可查、但不挡路"。
- `simulated` 如实标注（气泡里常驻「含演示数据」徽标），模型不可用时只标「基础回答」
  （不给用户看模型名与 `degraded`）；工具名映射成人话（`TOOL_LABELS`），没登记的显示原名。
- 请求失败也要落一条带「重试」的 agent 消息（不让用户的问题悬在原地）；
  等待时给三个跳动的点 + 一行"正在做什么"，而不是一句干等的文案。
- 输入区是**常驻底部**的玻璃条（`position: fixed` + 安全区），
  页面容器留出它的高度；对话只留在内存（刷新即清空，页面底部写明）。

发现页的开发工具、Mock 控制保持可用但折叠展示。
消息页保留订阅动作和空态，不制造虚假未读数。详情页保留参团、分享、地图与错误恢复。
全站保留第三方非官方说明。敏感模块的同意判断不能因视觉修改而移除。

## 字体与 WXSS 约束

图标字体**不做网络加载**：`src/presentation/theme/icon-font.scss` 把 Taroify（vant）图标字形
以 base64 内联，并在 `config/index.ts` 里用 alias 接管 `@taroify/icons/style/index.js`
（见 `src/presentation/theme/taroify-icon-style.ts`），先加载官方字形映射再覆盖官方那条
指向 `//at.alicdn.com` 的 `@font-face`。原因：协议相对地址在部分基础库不解析，
真机还必须把 `at.alicdn.com` 加进「下载合法域名」，否则图标全是空白方框。

写样式时不要使用 WXSS 不支持的选择器，否则 `common.wxss` 编译失败、**所有页面一起白屏**：

- 禁止 `.a > :first-child` / `.a > *` 这类「组合器 + 隐式通用选择器」写法，
  改成给子元素显式类名（`.a .kdy-field { flex: 1 }` 这类后代选择器是安全的）。
- 禁止裸 `*` 选择器；`@font-face` 的 `src` 禁止写 http(s) 或 `//` 网络地址。

`src/presentation/theme/__tests__/wxss-safety.test.ts` 会在单测里扫描全部 `.scss` 守住这三条。
