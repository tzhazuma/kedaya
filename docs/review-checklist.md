# 微信小程序提审材料清单（可达鸭）

> 这份清单面向**要按下「提交审核」的那个人**。
> 它只写「必须有什么、去哪儿拿、怎么自检」，不写愿望。
> 配套文档：部署见 [`deploy.md`](./deploy.md)，规划见 [`delivery-plan.md`](./delivery-plan.md)，
> 命名风险见 [`adr/0005-brand-and-ip.md`](./adr/0005-brand-and-ip.md)。

**顺序很重要**：主体与类目 → 域名与备案 → 服务上线（`deploy.md`）→ 隐私指引 →
内容安全 → 材料与截图 → 提审。**倒过来做会白跑一趟**：
类目和资质没过，后面所有材料都要重做。

## 0. 一句话现状（写清单时的事实，不要照抄）

- 后端可部署（微信云托管 + 托管 PostgreSQL），迁移与验收步骤见 `deploy.md`。
- 六条业务线（拼单 / 跳蚤 / 跑腿 / 找搭子 / 失物 / 论坛）+ 四条核心（身份 / 课表 /
  校园卡 / 我的-隐私与数据）+ 助手「可达鸭」已实现。
- **校园数据是模拟的**（`CAMPUS_DATA_MODE=mock`，响应标 `simulated: true`，UI 标「演示数据」）。
- **校园 CAS 身份仍是开发用 Mock**：审核员**不可能**用校园身份登录。
  所以必须提供**邮箱账号**（见 §6）。
- 高敏模块（`wellbeing` / `ai-portrait`）**未实现**，首页宫格点了会明确提示
  「契约已登记，尚未实现」—— 这是刻意的，不是漏做。

## 2. 域名、备案与合法域名

1. API 必须 **HTTPS**（TLS 1.2+），证书有效且链完整。
2. 微信后台 → 开发管理 → 开发设置 → **服务器域名**：
   - `request` 合法域名：API 域名
   - `uploadFile` 合法域名：**与 request 相同**（图片是服务器中转上传）
   - `downloadFile` 合法域名：图片访问域名（如果与 API 同域就填同一个）
3. 图片域名如果是对象存储（COS/OSS），**必须单独加进 downloadFile 白名单**，
   否则线上表现为「文字都在、图全是坏图」。
4. 小程序端 `project.config.json` 的 `appid` 必须换成**正式 AppID**（当前是占位）。

自检：用手机 4G（不要连校园 Wi-Fi）打开体验版，列表、图片、登录全跑一遍。

## 4. 隐私：用户隐私保护指引 + 隐私协议

微信要求在后台填写**《用户隐私保护指引》**，且必须与小程序**实际采集行为一致**。
不一致是最常见的驳回原因之一。下表就是需要逐项对照的清单（依据实现，不是依据设想）：

| 采集项 | 为什么 | 存哪 / 多久 | 备注 |
| --- | --- | --- | --- |
| 邮箱 | 登录、找回密码、绑定 | 数据库；账号存续期间 | 密码是 scrypt 哈希，**我们不存明文密码** |
| 微信 openid | 快捷登录、绑定微信 | 数据库；账号存续期间 | 不获取手机号、不获取通讯录 |
| 昵称、头像 | 展示 | 数据库 | 用户可改；头像可选 |
| 用户上传的图片 | 二手/失物/论坛内容 | 对象存储 | **服务端段级剥离 EXIF**（含 GPS）；地址白名单，不存外链 |
| 校园身份（学号等） | 校园功能 | 加密落库 + 审计 | 当前是**模拟数据**，未对接校方真实系统 |
| 客户端错误日志 | 崩溃排查 | 数据库 30 天 | 已脱敏（token/邮箱/手机号替换）、截断、限流。**不含正文与图片** |
| 文本地点（跑腿） | 任务展示 | 数据库 | **不调用定位接口**，不采集精确位置 |

**明确没有采集**：通讯录、剪贴板（除用户主动点「复制分享链接」）、精确地理位置、
相册（除用户主动选图）、麦克风、摄像头、第三方广告或统计 SDK。

其他必填项：
- [ ] 未成年人条款（校园场景一定要有：18 岁以下需监护人同意）
- [ ] 账号注销路径（`profile` 下的隐私与数据页）
- [ ] 数据导出/删除说明与联系方式
- [ ] 心理支持类文案（`wellbeing` 相关）**只在首页展示热线提示**，未实现模块不给假承诺

## 5. UGC 内容安全（审核最可能卡这里）

### 5.1 已有的

- **举报入口**：举报覆盖**公开的 UGC**——五个社交详情页底部有「举报这条内容」，
  **论坛每条回复**也能单独举报，另有三类同学共建内容（食堂菜品 / 常见问题 / 动物观察点）。
  原因白名单 7 项 + 可选补充说明；重复举报去重（409）；不能举报自己。
  **偷外卖刻意不在可举报范围内**：它是本人可见的报备记录，列表按登录主体过滤，
  本来就看不到别人的内容。
- **处理机制**：举报落库 + `[moderation]` WARN 日志；同一内容被 **3 个不同的人**举报会打
  `escalated` 标并告警。**刻意不自动下架**（自动下架等于给任何人一个「凑三个人删帖」的按钮），
  下架是人工复核后的动作，SQL 与流程见 `deploy.md` §5.6。
- **审核时效承诺**：请在后台/客服话术里写明**处理时限**（建议 24 小时内），
  并确保真有人看日志。承诺了却做不到，比不承诺更糟。

### 5.2 真实的缺口（**提审前必须决策**）

- ⛔ **内容安全接口未接入**：微信提供 `security.msgSecCheck`（文本）与
  `security.imgSecCheck`（图片），第三方（如云托管的内容安全服务）也可。
  目前只有「举报 + 人工复核」。**UGC 类小程序提审时这是最常见的驳回点。**
  接入位置：发布动作所在的六个模块服务方法之前（建议提成一个
  `ContentModerationPort` + 适配器，与 `MediaStoragePort` 同构），
  拒绝理由要回给用户（而不是静默丢失内容）。
- ⛔ **昵称/简介等用户可控文本**同样需要过一遍内容安全。
- ⛔ **审核时效与值班安排**：微信会问「违规内容多久处理」。需要一句可兑现的承诺。

### 5.3 页面上的合规文案（已完成，截图时不要裁掉）

- 非官方声明：每个模块详情页底部都有「第三方非官方校园服务平台，与上海科技大学官方系统无关」。
- 资金声明：拼单/跑腿写明「同学间自行结算，平台不参与资金往来」——
  **不要让审核员以为平台代收资金**，否则会被要求支付/资金资质。
- 演示数据标注：校园数据页显示「演示数据」（`simulated: true`）。

## 8. 已知会被驳回 / 需要拍板的风险点

| # | 风险 | 影响 | 建议 |
| --- | --- | --- | --- |
| 1 | **内容安全接口未接入**（§5.2） | UGC 类目最可能被驳回 | 提审前接入，或准备好「举报 + 24h 人工复核」的说明并接受一次补交 |
| 2 | **校园 CAS 未接通**（Mock） | 审核员无法用校园身份体验 | 提供邮箱账号（§6.1），并在备注里说明 |
| 3 | **命名与角色 IP 风险**（ADR 0005） | 名称可能被驳回，或上线后被投诉下架 | 这是**未消解**的风险，需要决策者显式选择「改名」或「承担」。注意：ADR 里已确定「不使用第三方角色美术」，但**名称本身**的风险仍在 |
| 4 | 二手交易 + 悬赏 | 可能被要求交易资质 | 文案已明确「平台不参与资金往来」；不要加任何代收代付功能，否则性质改变 |
| 5 | 心理支持相关内容 | 属敏感题材 | **已上线的只有倾听与预约**：首屏危机出口（`110`/`120` + 辅导员/保卫处）、
同意门、预约与取消；**没有测评、没有诊断、没有治疗**（量表刻意不做）。提审时如实说明，并截图 §6.2 的 9–10 |
| 6 | **危机热线号码未经核实** | 号码错/停用会在最需要的时候失效 | 上线前**逐个拨通**核实（代码内有 `WELLBEING_CRISIS_VERIFY_NOTE`），号码可用 `WELLBEING_CRISIS_*` 覆盖，不必发版 |
| 7 | **AI 画像目前没有生成逻辑** | 审核员点进去看到空态，可能问"功能在哪" | 空态文案已写明「还没有足够的数据生成画像」；如实说明"画像生成未接入，先交付可解释、可关闭的框架" |
| 8 | 个人主体 | 类目受限 | 走企业/组织主体 |
