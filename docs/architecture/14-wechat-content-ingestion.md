# 14 · 公众号内容接入：能做什么、不能做什么

> 2026-10-20。回答：「公众号我记得是有类似网址的地址的，尝试去爬取」。
>
> **结论先说**：单篇文章**可以**抓，而且已经实现并测通；
> **批量抓取历史文章不可行**（违反微信条款，且技术路径已失效）。

---

## 1. 先分清两件事

| | 单篇文章 | 批量历史文章 |
| --- | --- | --- |
| 形态 | `https://mp.weixin.qq.com/s/<id>` 这是**公开网页** | 需要登录态 Cookie 打内部接口 |
| 可行性 | ✅ **实测可以**（2026-10-20） | ❌ 技术上不稳定、条款上不允许 |
| 我们的做法 | ✅ 已实现 `parseWechatArticle` | ❌ 不做 |

### 实测记录（2026-10-20）


## 2. 为什么批量抓不了

### 技术原因

微信**没有**公开的「公众号历史文章」API。想拿列表只能：

| 路径 | 现状 |
| --- | --- |
| `mp.weixin.qq.com/mp/profile_ext?action=getmsg` | 内部接口，需要 `__biz` + `uin` + `key` + `pass_ticket`。Cookie **几小时就失效**，且频繁请求会触发风控 |
| 搜狗微信搜索 | 已大幅收紧，返回结果不完整且不稳定 |
| 第三方 RSS 桥（如 RSSHub 的 wechat 路由） | 依赖上面两条，本质是同一个问题；且需要额外的代理服务 |
| 微信「发布能力」API | **只对你自己运营的公众号有效**，不能读别人的 |

### 条款原因

> 未经授权采集微信公众号内容，违反《微信公众平台服务协议》与《微信外部链接内容管理规范》。

这是**平台规则**，不是「有没有授权」的问题 —— 即便学校同意了，微信那一侧也没同意。

**所以我们的做法是：不做爬虫，做「把用户已经能看到的文章读出来」。**

## 3. 已经实现的：单篇解析

### 模块

`packages/shared/src/wechat-article.ts`（26 条测试）

```ts
import { parseWechatArticle, looksLikeWechatArticle } from '@kedaya/shared';

// 调用方自己取 HTML（服务端 fetch 或用户粘贴）
const result = parseWechatArticle(html, url);
if (!result.ok) {
  // result.error.code: login-required | empty-page | unrecognized-structure
  // result.error.message 已经是能直接给用户看的中文
}
// result.value: { title, accountName, publishedAt, bodyLines, images, sourceUrl }
```

### 三条设计决定

#### ① 「打不开」的四种原因要分开说

| 情况 | 页面特征 | 我们给用户的提示 |
| --- | --- | --- |
| 风控验证 | 含「环境异常」 | 微信要求验证环境，请稍后再试 |
| 已删除 | 含「该内容已被发布者删除」 | 文章已被发布者删除 |
| 违规下架 | 含「此内容因违规无法查看」 | 文章因违规无法查看 |
| 需微信内打开 | 含「请在微信客户端打开链接」 | 该文章要求在微信客户端内打开 |

**四种提示互不相同**（有测试锁死）。笼统的「解析失败」会让用户以为是自己操作错了。

#### ② 发布时间不许拿抓取时间冒充

微信只在页面里给 **unix 秒**（`var ct = "1694078981"`），**不带时区**。

我们按 `Asia/Shanghai` 解释（公众号读者就是国内用户，这是唯一合理假设），
输出带 `+08:00` 偏移的字符串。**读不到就返回 `null`** —— 不用当前时间顶上。

#### ③ 正文容器为空 ≠ 解析成功

有页面骨架但 `js_content` 里没内容，典型是「关注后可见」。
此时返回 `login-required` 并提示「可能要求关注公众号后查看」，
**不返回半篇正文** —— 半篇比没有更糟（用户会以为文章就这么短）。

> ⚠️ 踩过的坑：一开始只检查「剥掉标签后有没有文字」，
> 结果把**纯图片通知**（很多通知就是一张长图）误判成「需关注后查看」。
> 现在「有文字」**或**「有图片」任一成立就算非空。

## 4. 从文章到「活动/DDL」还差什么

公众号文章是**自然语言**，没有结构化字段。硬抽会把「2023级」识别成日期。

所以我们只用两层：

### 第一层：粗筛（已实现）

`pickEventCandidateLines(lines)` —— 挑出**同时**含时间线索与地点/报名线索的段落：

```ts
const candidates = pickEventCandidateLines(article.bodyLines);
// ["讲座时间：10月25日 14:00，地点：信息学院 1-101"]
```

### 第二层：精解（复用已有）

把粗筛出的每一段交给**唯一的时间解析入口** `parseDueText(raw, now, timeZone)`。
它已经在 DDL 聚合里用了 500+ 条测试，不重复造。

### 没做的

- ❌ **不做「自动发现学校所有公众号」** —— 那需要爬虫
- ❌ **不做「定时轮询文章列表」** —— 同上
- ✅ 做的是：**用户把某篇文章的链接给可达鸭，我们解析这一篇**

## 5. 产品上怎么用

三条可行路径，按推荐度：

| # | 形态 | 说明 |
| --- | --- | --- |
| A ⭐ | **小程序「分享到可达鸭」** | 用户在微信里读到活动通知 → 点「···」→ 分享 → 选可达鸭 → 我们解析这一篇，把时间地点填进日程 |
| B | Web `/import` 粘贴链接 | 已部署的 Web 端 `https://<web>/import` 可以扩展一个「公众号链接」输入框 |
| C | 管理员维护「学校公众号清单」 | 管理员手工列出几个官方号，我们只**验证链接**（不是爬列表），用户点进去看 |

**A 最符合微信的习惯**，也完全绕开了爬虫问题 —— 用户主动分享，我们只是解析。

## 6. ✅ 服务端端点已实现（2026-10-20）

`POST /api/v1/wechat/article`（`services/api/src/modules/wechat/`）

```jsonc
// 请求
{ "url": "https://mp.weixin.qq.com/s/xxxxx" }

// 成功
{ "ok": true, "article": { "title", "accountName", "publishedAt", "bodyLines", "images", "sourceUrl" } }

// 业务性失败（仍然是 HTTP 200，用 ok 区分）
{ "ok": false, "code": "login-required", "message": "正文容器是空的 —— …" }
```

### ⚠️ 三条安全边界（这个端点接受用户给的 URL，必须有）

| 边界 | 为什么 |
| --- | --- |
| **域名白名单：只认 `https://mp.weixin.qq.com/s/`** | 不做的话它就是一个**内网 SSRF 跳板** —— 攻击者可以让服务器去请求 `169.254.169.254`（云元数据）或 `localhost:3100`（我们自己的 API） |
| **不跟随跳转**（`redirect: 'manual'`） | 跳转是绕过域名白名单的常见手法 |
| **限制体积与超时** | 12 MB / 12 s。否则一个超大响应能把进程拖死 |

有 33 条测试锁着，其中 8 条专门验证**被拒绝的 URL 根本不会发出请求**
（`expect(fetchMock).not.toHaveBeenCalled()`）。

### 为什么失败返回 200 而不是 4xx

「文章要求关注后查看」是**业务结果**，不是客户端错误。
用 4xx 会让前端把它渲染成「请求失败」，**盖掉那句有用的解释** ——
和付款码那次「POST 得到 405、405 盖掉 503」是同一类错误。
