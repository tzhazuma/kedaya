# 校园拼单首版规则

本文件记录校园熟人群拼单的产品规则。拼单用于登记需求、汇总采购清单和组织线下取货；平台不接收订单付款，也不记录“已收款”。

## 凑凑入口

产品一级入口命名为「凑凑」，下设「拼单」和「找搭子」。原独立「找搭子」入口从 Web、小程序和 Flutter 模块宫格移除；现有 `buddy` API 和数据结构保留，供后续接入凑凑内的找搭子页面。目前找搭子发布与报名页面尚未实现，前端明确展示建设中状态。

## 拼单类型

- 普通拼单：任意已登录校园用户可发起、参团。
- 会员代购拼单：仅完成对应商家会员资格核验的用户可发起，任意已登录校园用户可参团。核验能力上线前，只能显示“发起人自述持有会员”，不能显示平台认证标识或声称系统已限制发起资格。

两种类型共用拼单、成员和汇总模型，不拆成两套交易流程。

## 成团与截止

- 发起人设置目标总份数 `targetQuantity`，必须为正整数。成员登记 `quantity`，各成员有效份数之和为 `joinedQuantity`。参与人数 `participantCount` 独立展示，不参与成团判断。
- 发起人只有登记了自己的需求才计入份数；仅创建拼单不自动占一份。
- `joinedQuantity >= targetQuantity` 时成团，后端在同一事务中更新成员和拼单状态。
- 截止时间固定为创建时间后 24 小时，不由用户设置。到达截止时间时仍未成团，自动取消，原因记为 `TIMEOUT_24H`；已成团的拼单不受超时规则影响。
- 成团前，成员可修改自己的份数或退出；成团后清单锁定。发起人可在成团前手动取消，原因记为 `CREATOR_CANCELLED`。
- 前端倒计时只用于显示；能否参团、是否成团和超时取消始终以服务端时间和状态为准。

## 信息与页面

发起人填写标题、商品/规格、说明、目标总份数、取货地点，以及可选参考单价。会员代购还需填写商家和会员说明。参团者填写每项商品的份数和可选备注；同一用户只保留一份当前有效登记，可反复修改。

列表展示类型、标题、状态、`joinedQuantity / targetQuantity`、参与人数和剩余时间。详情展示商品清单、成员登记、修改/退出入口，并提供“按商品汇总”和“按成员汇总”的可复制文本。发起人可分享至微信群；成团后可发布取货通知并逐人标记已领取。成员联系信息默认不公开。

## 实现边界

- 写操作要求可达鸭校园账号。会员商家的账号、卡号和登录凭据不得交给平台代存。
- 创建与修改/参团请求使用幂等键；数据库事务内校验剩余份数，防止并发超额。
- 定时任务负责取消到期未成团的拼单；读取和写入时也应兜底检查到期状态。
- 首版不做在线支付、收退款、优惠券、佣金、物流和商家订单同步。
- 现有 Web、小程序、Flutter 与 API 对状态、人数和份数字段有差异；接入真实 API 前，先统一共享契约和传输 DTO。
