## 2. 背景

### 2.1 名字的来源

| 项 | 值 |
| --- | --- |
| 产品名 | **可达鸭** (KedaYa) |
| 英文标识 | `kedaya` |
| 全称 | 上海科技大学 · 统一校园服务平台 |
| Slogan | 上科大，什么需求都可以到达 |
| 名字含义 | 可达鸭 = "在上科大什么需求都可以**到达**" 的**鸭** |

**命名的原始意图与宝可梦无关**：它取自「**可达**」（什么需求都可以到达）+ 「**鸭**」（吉祥物形象）。这是一个**双关构造**，不是对宝可梦角色的引用。

**但意图不决定法律后果。** 见 §3。

### 2.2 吉祥物（美术）的来源

| 项 | 值 |
| --- | --- |
| 资产路径 | `assets/brand/kedaya-mascot.svg` |
| 来源 | **原创**。为 KedaYa 项目单独绘制 |
| 与第三方角色的关系 | **无**。不基于任何现有角色形象 |

**「原创美术」这条是可辩护的**（见 §3.3），前提是：
- 绘制过程**没有**参考宝可梦可达鸭的具体形象（体态、配色方案、眼睛形状、喙的形状、手脚造型等）；
- 保留创作过程证据（草图、时间戳、作者声明）。

**这不是自动成立的**——"原创"需要在被质疑时能**证明**。见 §4 的硬规则。

## 3. 风险事实

### 3.1 事实一：「可达鸭」是任天堂的官方中文角色名

| 事实 | 说明 |
| --- | --- |
| 「可达鸭」是宝可梦系列角色 **Psyduck** 的官方中文译名 | 不是民间俗称，是官方名称 |
| Psyduck 首次登场于 1996 年的《宝可梦 红/绿》 | 时间远早于本项目 |
| 中国知识产权报（国家知识产权局主管报纸）报道原文 | > 「可达鸭是任天堂发行的掌机游戏"宝可梦"系列和根据它改编的宝可梦动画中登场的虚构角色怪兽中的一种，进入中国后，任天堂对其进行了知识产权布局。」 |

来源：[「可达鸭」引热议，商标布局需这般……](https://iprchn.com/cipnews/news_content.aspx?newsId=134591)（中国知识产权报，2022-05-27；[转载版](https://www.ciplawyer.cn/articles/148402.html)）

### 3.2 事实二：任天堂在中国已注册「可达鸭」商标，并持续维权

| 事实 | 数据 | 来源 |
| --- | --- | --- |
| 任天堂开始在中国布局「可达鸭」商标 | **自 2017 年起**，已在**多个商品和服务类别**上被核准注册 | 同上 |
| 「可达鸭」相关商标申请总数（截至 2022-05-24） | **50 件** | 同上 |
| 「PSYDUCK」相关商标申请总数 | **9 件** | 同上 |
| 申请主体 | 任天堂**之外**还有武汉联创优品贸易有限公司、湖南景悦箱包股份有限公司等**多个市场主体或个人** | 同上 |
| 已被注销 / 异议 / 宣告无效的「可达鸭」商标 | **多件**，涉及嘉兴市绯客商贸有限公司、湖州市织里翔宇服装厂等 | 同上 |

**对我们的含义**：
1. 任天堂在**多个类别**持有该商标 → 我们在**任何类别**使用都可能落入其保护范围。
2. 第三方申请的「可达鸭」商标**被大量无效掉** → 说明任天堂在**主动维权**，且**维权有效**。
3. 我们作为校园服务，虽然不直接销售商品，但**小程序名称、应用名、域名、服务标识**都可能构成"商标性使用"。

### 3.3 事实三：专家意见指向「在先权益 + 可能受著作权保护 + 角色名称受保护」

这是本 ADR 最关键的一段。两位专家在同一篇报道中的意见：

**武汉大学知识产权与竞争法研究所所长 宁立志**：

> 「首先，任天堂创造可达鸭角色的时间早于其他市场主体或个人申请注册"可达鸭"商标的时间，对其享有**在先权益**；其次，可达鸭一词是**臆造词**，即便其长度仅为三个字，也依然可能具备一定**独创性**，从而被直接视为**受著作权法保护的作品**；最后，即便认为可达鸭不能单独构成著作权保护客体，但**具有一定知名度的角色名称依然受法律保护**。」

**中国法学会知识产权法学研究会理事、中央民族大学法学院副教授 熊文聪**：

> 「一个有一定知名度的符号组合到底是哪种权利或权益的保护对象，要根据**被使用的语境**来确定。如果使用者是将某符号组合使用在自己的文艺表达中以**减省自己的创作成本**，那就是从**著作权**角度予以保护；如果使用者是将该符号组合用于**指代相同或类似的商品**，从而让消费者对商品来源产生**混淆误认**，那就是从**商标**角度予以保护。在该事件中，部分将"可达鸭"注册为商标的经营者，是想**搭"可达鸭"所承载商誉的便车**，或涉嫌侵犯任天堂享有的**已经使用并有一定影响的未注册商标权益**。」

**逐条映射到我们身上（这是最难受的部分，必须直说）**：

| 专家的论点 | 我们的情况 | 风险判定 |
| --- | --- | --- |
| 任天堂享有**在先权益** | 我们的项目时间远晚于 1996 年 | **直接适用，不利** |
| 「可达鸭」是**臆造词**，可能有独创性 | 我们的名字**完全相同** | **直接适用，不利** |
| 角色名称**受法律保护** | 我们用的是**角色名称本身** | **直接适用，不利** |
| 著作权角度：是否"减省自己的创作成本" | 我们**没有**复用其形象（美术原创），但**复用了其名称** | **部分适用**——名称这一项是减省了（我们直接用了现成的名字） |
| 商标角度：是否造成**混淆误认** | 我们不是商品销售，但用户可能误以为与宝可梦有关 | **可能适用** |
| 是否"搭商誉便车" | 我们**不追求**这个，但客观上「可达鸭」的知名度**会**给我们带来流量 | **客观适用**——动机不影响认定 |

**结论**：**我们无法主张"因为意图是双关所以不侵权"。** 法律看的是客观使用与混淆可能性，不是主观意图。

### 3.4 事实四：任天堂在中国的维权是真实且高额的

| 案例 | 结果 | 来源 |
| --- | --- | --- |
| 6 家中国开发商抄袭《宝可梦》 | 判赔**近新台币 5 亿元**（约人民币 1.1 亿元） | [中时新闻网报道](https://www.chinatimes.com/cn/realtimenews/20250224002537-260412)（该站对自动化访问返回 403，链接为人工可访问） |
| 《宝可梦》在华维权首案 | 广东高院依托「严格审查+示范判决+国际调解」促成跨国知产诉讼达成**调解** | [广东政法网](https://www.gdzf.org.cn/zwgd/content/post_180167.html)（该站对自动化访问不可达，链接为人工可访问） |
| 海关对出口侵犯「POKEMON」商标专用权商品的行政处罚 | 2025 年有多起（深鹏关知罚字〔2025〕0228 号等） | 海关行政处罚公示 |

**含义**：任天堂不是"发个律师函就算了"的权利人。它有**跨境诉讼**、**行政投诉**、**海关查扣**的完整手段，且**在中国法院有胜诉与高额判赔记录**。

**对我们（非商业校园项目）的实际风险画像**：

| 风险类型 | 概率 | 影响 |
| --- | --- | --- |
| 收到律师函 / 侵权通知，要求改名 | **中** | 需要改名（可控，但有成本） |
| 小程序审核被拒 / 被下架（权利方投诉） | **中** | 主端不可用（严重） |
| 应用商店下架（App Store / Play / AppGallery 投诉） | **中** | 原生端不可用 |
| 域名争议（UDRP / CNNIC 域名争议） | 低（若域名不含 `psyduck`） | 域名被收回 |
| 诉讼与判赔 | **低**（我们非商业、无获利、规模小） | 若发生则严重 |
| 学校层面的合规压力 | 中 | 项目可能被要求停止 |

**为什么"非商业"能显著降低但不消除风险**：

| 因素 | 对赔偿的影响 | 对"是否侵权"的影响 |
| --- | --- | --- |
| 非商业、无获利 | 显著降低赔偿额（无违法所得） | **无影响**——侵权认定与是否获利无关 |
| 规模小、学生项目 | 降低权利人的维权动机 | 无影响 |
| 显著标注非官方 | 降低混淆可能性 | **有影响，有利** |
| 不使用官方素材 | 排除著作权侵权 | 但**不排除商标/名称侵权** |
| 有原创吉祥物 | 排除美术著作权侵权 | 但**不排除名称侵权** |

**一句话总结**：**我们最可能被要求"改名"，而不是被索赔。但"改名"对我们来说已经是重大成本**（小程序名称变更、应用重新提交、域名更换、用户认知重建）。

### 3.5 事实五：商标检索的时效性缺口（诚实标注）

| 项 | 状态 |
| --- | --- |
| 我引用的数据时点 | **2022-05-24**（中国商标网检索结果，来自 2022 年的报道） |
| 2022 年之后任天堂是否新增注册 | **未知** |
| 2025/2026 年的最新商标状态 | **未知** |
| 我们**没有**做过的检索 | ① 中国商标网实时检索；② 我们拟使用的类别（第 9 类软件、第 41 类教育娱乐、第 42 类技术服务）是否有**他人**注册；③ 是否有**在先的「可达鸭」软件/小程序** |

**这是一处必须承认的证据缺口。** 本文档的所有风险判断基于 **2022 年的公开报道**。见 §8 门禁 G-IP1。

## 4. 规避方案（技术层面可执行的硬规则）

### 4.1 绝对禁止清单（**任何 PR 违反即拒绝合并**）

| # | 禁止事项 | 检查方式 |
| --- | --- | --- |
| N1 | 禁止引入任天堂/宝可梦的**任何图像素材**（含官方立绘、截图、表情包、同人图） | `assets/` 目录审查 + 图片哈希比对 |
| N2 | 禁止使用「宝可梦」「Pokémon」「Pokemon」「任天堂」「Nintendo」「Game Freak」「The Pokémon Company」等词 | 全仓文本扫描（含代码、文案、注释、README） |
| N3 | 禁止在吉祥物美术中复刻宝可梦可达鸭的**可识别特征组合**：① 黄色圆身 + ② 三根黑色呆毛 + ③ 蹼状手 + ④ 呆滞无神的大眼 + ⑤ 扁喙 | 美术评审 checklist（§4.3） |
| N4 | 禁止任何"官方"暗示：不得使用「官方」「授权」「合作」「正版」等词描述与学校/任天堂/宝可梦的关系 | 文案审查 |
| N5 | 禁止商业化：收费、广告、付费会员、融资、出售数据 | 产品决策 |
| N6 | 禁止在应用商店/小程序描述里使用宝可梦相关的关键词做 ASO | 上架文案审查 |
| N7 | 禁止注册含 `psyduck` / `pokemon` / `pikachu` 等词的域名 | 域名清单审查 |
| N8 | 禁止将「可达鸭」用于**商品销售**（周边、T 恤、贴纸等实物） | 这是商标侵权风险最高的场景 |

**N8 特别说明**：校园项目很容易想"做点周边送人"。**这是风险最高的动作**——实物商品 + 商标性使用 + 可能有对价（哪怕只是成本价）。**明确不做。**

### 4.3 吉祥物美术评审 checklist（必须逐条通过）

设计一个**与宝可梦可达鸭可区分**的原创形象。逐条检查：

| # | 特征 | 宝可梦可达鸭 | 我们的要求 |
| --- | --- | --- | --- |
| 1 | 主体配色 | 明黄色（单一） | **必须不同**——建议品牌色 `#FFC53D`（暖黄）+ `#1B2436`（深墨）**双色结构**，或改用其它主色 |
| 2 | 头部造型 | 圆头 + 头顶三根黑色呆毛 | **必须不同**——不做三根呆毛；改做**一撮呆毛**或**无呆毛** |
| 3 | 眼睛 | 大而圆、无神、瞳孔小 | **必须不同**——改做**有明确高光的椭圆眼**或**月牙眼** |
| 4 | 喙 | 扁平鸭喙、浅色 | **可以保留"鸭喙"这个物种特征**（鸭是通用形象，不受保护），但**形状必须不同**（如更短、更尖、或带品牌色） |
| 5 | 手 | 蹼状、短小 | **必须不同**——改做**握拳/招手的手**或**无手（翅膀造型）** |
| 6 | 身体比例 | 头身比约 1:1.2 的圆润体型 | 建议改做**更修长**或**更方正**的比例 |
| 7 | 附加元素 | 无 | **建议增加独有元素**——如**学士帽**、**校园卡**、**书本**、**眼镜**（体现"校园服务平台"定位） |
| 8 | 整体印象 | — | 给 3 个不了解项目的人看，问"这像什么"——**若有人答"可达鸭/宝可梦"，必须重做** |

**第 8 条是最实用的检验**：如果第一眼印象就是宝可梦可达鸭，那"原创"的辩护在法庭上会很弱。

**建议的差异化方向**：把吉祥物定位成"**一只在校园里跑腿的鸭**"——带学士帽、脖子上挂校园卡、手里拿快递盒。这些元素**明确指向校园服务**，与宝可梦可达鸭的"野生水属性宝可梦"设定完全不同。**这是最有效的差异化：不是改外形，而是改设定。**

### 4.4 展示权重方案

| 场景 | 展示内容 | 理由 |
| --- | --- | --- |
| 应用图标 | **纯图形**（吉祥物剪影或字母 K），**不含文字** | 避免名称进入图标这一"商标性使用"最强的位置 |
| 小程序名称（微信后台） | `可达鸭 · 上科大校园服务` | 微信要求名称唯一，且需带功能描述 |
| 小程序首页标题 | `可达鸭` + 副标题 `上科大校园服务平台（非官方）` | 显著标注 |
| App 名称（桌面图标下方） | **`KedaYa`** | 用英文名，降低中文名的商标性使用强度 |
| App Store / Play / AppGallery 名称 | `KedaYa 可达鸭 · 上科大校园服务` | 商店搜索需要中文关键词，但英文名在前 |
| 域名 | **不含「可达鸭」拼音**——建议 `kedaya.app` / `kedaya.club` | 域名是最容易被主张"商标性使用"的资产 |
| 代码标识符 | `kedaya` / `KedaYa` / `@kedaya/*` | 已是现状（契约 §3 §6） |
| 关于页 | 完整的免责声明 + 原创美术声明 + 名称由来说明 | 见 §4.6 |
| README / GitHub 仓库 | 英文名 + 免责声明 + 名称由来说明 | 开源场景同样需要 |

**`kedaya` 这个标识本身的风险**：「kedaya」是「可达鸭」的拼音，**读音与「可达鸭」完全相同**。在法律上，拼音标识与中文商标的近似判断是**可能构成近似**的。**所以 D5（优先英文名）降低的是视觉混淆与检索命中，不是法律近似性。** 这一点不能自我安慰。

**真正安全的标识**是**与「可达鸭」无读音关联**的（如 `shanghaitech-helper`），但那已经不是品牌了。见 §6 降级预案。

### 4.5 品牌名称的可配置化（技术准备）

**要求**：品牌名称不得硬编码在业务代码里。

```ts
// packages/contracts/src/brand.ts（形状示意）
export const BRAND = {
  /** 内部标识，永不变更。用于包名、路径、DB 前缀 */
  id: 'kedaya',
  /** 展示名。可配置。降级时改这里 */
  displayName: process.env.NEXT_PUBLIC_BRAND_DISPLAY_NAME ?? '可达鸭',
  /** 英文展示名 */
  displayNameEn: 'KedaYa',
  /** 副标题（含非官方标注） */
  tagline: '上科大校园服务平台（第三方非官方）',
  /** 免责声明全文 key，指向 copy/brand.ts */
  disclaimerKey: 'brand.disclaimer.v1',
} as const;
```

| 端 | 配置方式 |
| --- | --- |
| Web（Next.js） | `NEXT_PUBLIC_BRAND_DISPLAY_NAME` 环境变量 |
| 小程序（Taro） | 构建期 `TARO_APP_BRAND_DISPLAY_NAME`，注入 `app.config.ts` 的 `navigationBarTitleText` |
| Flutter | 编译期 `--dart-define=BRAND_DISPLAY_NAME=...` |
| 后端 | 品牌相关的文案（通知模板）从 `@kedaya/contracts` 读，不硬编码 |

**为什么这个准备必须在 M0 做**：如果名字硬编码在 200 个文件里，降级就变成一次大重构。**可配置化把"改名"的成本从"重构"降到"改配置 + 重新提交应用"。**

### 4.6 免责声明文案（必须包含的要素）

必须包含且**不得含糊**：

1. 本平台是**第三方非官方**服务，**不代表**上海科技大学。
2. 本平台**与任天堂株式会社、株式会社宝可梦、The Pokémon Company 无任何关联**，未获其授权或认可。
3. 吉祥物为**本项目原创美术**，与任何第三方角色形象无关。
4. 名称「可达鸭」的由来：取自「什么需求都可以**到达**」+ 吉祥物形象，**非对任何现有角色的引用**。
5. 本平台**不商业化**，不收费、不投放广告。
6. 数据处理的说明（指向隐私政策，见 [05-security-privacy.md](../architecture/05-security-privacy.md) §9.5 G1）。

## 5. 风险矩阵（诚实评估）

| 风险 | 概率 | 影响 | 现有缓解 | 残余风险 |
| --- | --- | --- | --- | --- |
| 收到任天堂/宝可梦公司的侵权通知，要求改名 | **中** | 中（改名成本） | D5 英文名优先 + Y1 显著标注 + D4 非商业 | **中，未消解** |
| 微信小程序审核被拒或因投诉下架 | **中** | **高**（主端不可用） | 上架文案规避关键词 + 显著非官方标注 | **中，未消解** |
| 应用商店下架 | 中 | 高 | 同上 | 中，未消解 |
| 域名争议 | 低 | 中 | 域名不含「可达鸭」拼音（若采纳） | 低 |
| 著作权侵权（美术） | **低** | 中 | D1 原创美术 + §4.3 checklist + Y4 创作证据 | **低** |
| 著作权侵权（名称的独创性主张） | 中 | 中 | 无法缓解——名称本身就是争议标的 | **中，未消解** |
| 不正当竞争（搭便车认定） | 中 | 中 | 非商业 + 显著标注 + 不做 ASO | 中，未消解 |
| 学校层面的合规压力 | 中 | **高**（项目可能被要求停止） | 显著标注非官方 + 与学校沟通 | **中，未消解** |
| 舆论风险（被指"蹭宝可梦热度"） | 中 | 中 | 名称由来说明 + 原创美术 + 非商业 | 低-中 |
| 诉讼与判赔 | 低 | **高** | 非商业、无获利、规模小 | 低 |

**加粗的「未消解」是本 ADR 的核心结论：名称风险无法通过技术手段消除，只能通过"改名"消除。**

## 6. 命名降级预案

### 6.1 触发条件

满足**任一**即触发降级评估：

| # | 触发条件 | 判定人 |
| --- | --- | --- |
| C1 | 收到任何形式的侵权通知 / 律师函 / 平台投诉 | Lead |
| C2 | 微信小程序或任一应用商店因名称问题被拒/下架 | Lead |
| C3 | 学校要求改名 | Lead |
| C4 | 上线前的商标检索（§8 G-IP1）显示高风险 | Lead + 法务 |
| C5 | 舆论事件（被广泛指为"蹭宝可梦"） | Lead |

### 6.2 候选名称评估

| 候选 | 与「可达鸭」/宝可梦的关联 | 品牌价值 | 商标可注册性（**未检索，需验证**） | 评价 |
| --- | --- | --- | --- | --- |
| **`KedaYa` / `kedaya`（仅英文）** | 拼音读音与「可达鸭」相同 | 中（保留品牌连续性） | 低-中（读音近似可能被认定） | **首选降级**：改动最小，保留品牌资产 |
| **「可达」** | 无（宝可梦无此角色） | 中（保留"到达"的含义） | **待检索** | **次选**：语义完整、简洁 |
| **「上科大鸭」** | 无 | 中 | 待检索（含学校名，可能有其他问题） | 可用，但"上科大"是学校简称，需确认使用规范 |
| **「校园鸭」** | 无 | 中 | 待检索 | 通用词，显著性弱 |
| **「什么都能到」** | 无 | 中 | 待检索 | 直接表达 slogan |
| **「科答鸭」** | 字形近似「可达鸭」 | 中 | **低**（字形近似风险高） | **不推荐**——换汤不换药 |
| **「可达鸭」改为「到达鸭」** | 字形/读音都近似 | 中 | **低** | **不推荐**——同上 |
| **完全新造名（如 `DuckGo` 类）** | 无 | 低（丢失现有认知） | 高 | 最后手段 |
| **不含鸭的通用名（如 `上科大助手`）** | 无 | 低 | 高 | 最安全但最无特色 |

**诚实说明**：
- 以上候选**全部未做商标检索**。「待检索」就是字面意思——**在检索之前不能假定任何一个是安全的**。
- 「科答鸭」「到达鸭」这类"擦边改字"是**最坏的选择**：既保留了侵权风险，又失去了原名的传播力。**明确不采用。**
- 真正安全的路径是**彻底切断与「可达鸭」的字形、读音、语义关联**——代价是品牌重建。

### 6.3 降级执行清单（成本预估）

| # | 动作 | 依赖 | 成本 |
| --- | --- | --- | --- |
| 1 | 改 `@kedaya/contracts` 的 `BRAND.displayName` | §4.5 的可配置化 | **极低**（前提是 M0 做了准备） |
| 2 | 改小程序后台名称 + 重新提交审核 | 微信平台 | 中（审核周期 + 可能被拒） |
| 3 | 改应用商店名称 + 重新提交 | 3 个商店 | **高**（App Store 审核 + 版本号 + 用户认知） |
| 4 | 改域名 + 301 跳转 + 保留旧域名 | DNS + 证书 | 中 |
| 5 | 改吉祥物（如需） | 美术 | 中 |
| 6 | 改全部对外文案与免责声明 | 文案 | 中 |
| 7 | 通知用户（站内信 + 公告） | `notifications` | 低 |
| 8 | 保留旧名的历史数据（不破坏 DB） | `BRAND.id` 永不变更（§4.5） | **零** |
| 9 | 更新 GitHub 仓库名/README | — | 低 |

**第 8 条是关键设计**：`BRAND.id`（`kedaya`）**永不变更**，只改 `displayName`。这样包名 `@kedaya/*`、数据库前缀、缓存键、路由路径全部不用动。**降级的影响面被限制在"展示层"。**

### 6.4 降级的时间预算

| 场景 | 时间 |
| --- | --- |
| M0 期间降级（未发布） | **数小时**（改配置 + 美术） |
| M1 期间降级（内测，无用户） | 1–2 天 |
| M2 期间降级（已有用户） | **1–2 周**（含应用商店重新审核与用户通知） |
| 上线后降级（大规模用户） | **2–4 周** + 用户认知损失 |

**结论**：**降级的成本随时间指数增长。** 这就是为什么 §8 的门禁 G-IP1（上线前商标检索）**必须在 M0/M1 完成**，而不是等到上线前。

## 7. 备选立场：为什么不直接改名

有人会问：**既然风险真实存在，为什么不现在就改名？**

| 支持保留「可达鸭」的理由 | 支持立即改名的理由 |
| --- | --- |
| 名字由来的双关是真实且巧妙的（"可达"+"鸭"） | 法律不认意图 |
| 已有品牌资产（仓库名、包名、文档、认知） | 资产可以迁移，成本随时间增长 |
| 非商业、校园项目，实际维权动机低 | "动机低"不等于"不会发生" |
| 显著标注非官方可降低混淆 | 降低混淆 ≠ 消除商标侵权 |
| 改名的成本（§6.4）在 M0 很低，但产品辨识度损失是永久的 | 一次律师函的成本远高于 M0 改名 |
| 很多校园项目都用类似名字且未出事 | 幸存者偏差 |

**本 ADR 的立场**：**暂不改名，但把"改名"变成一个低成本的配置操作，并在 M0/M1 完成商标检索与法律意见。**

理由：
1. 立即改名会失去一个真实有传播力的名字，而风险尚未被专业检索确认（§3.5 的缺口）。
2. 但**不做的代价必须被消除**——所以 D6/D7（可配置化 + 降级预案）是**不可谈判的**。
3. 若 §8 G-IP1 的检索结论是"高风险"，则**立即执行降级**，不再讨论。

**这是本 ADR 最诚实的一句话**：我们不是在说"没问题"，我们是在说"**问题已知，缓冲已备，门禁已设，等待专业结论**"。

## 9. 被否决的方案及理由

本节列出我们在品牌与 IP 上**考虑过但否决**的方案。这些方案都曾被真实讨论过，否决理由必须记录下来，否则未来会有人重新提出。

### 方案 A：不做任何规避，直接用「可达鸭」

**描述**：认为"校园非商业项目没人管"，不加免责声明、不做美术差异化、不做检索。

| # | 否决理由 |
| --- | --- |
| 1 | §3 的事实显示任天堂在**主动且有效**地维权（第三方商标被大量无效） |
| 2 | 无免责声明会**提高混淆可能性**，这是侵权认定中的核心要素之一 |
| 3 | 不做美术差异化会同时引入**著作权**风险（§4.3 第 8 条盲测会失败） |
| 4 | 不做检索等于**在未知风险下发布**，这与本项目的工程标准（契约 §10 要求可验证）不一致 |
| 5 | 代价不对称：规避成本极低（几份文案 + 一次评审），不规避的代价可能是改名或下架 |

### 方案 B：立即改名，彻底避开风险

**描述**：既然风险真实存在，在 M0 期间就换成无争议的名字（如「上科大助手」）。

| # | 否决理由 |
| --- | --- |
| 1 | 风险**尚未被专业检索确认**（§3.5 的证据缺口）。在结论出来前放弃一个有传播力的名字，是基于恐惧而非基于事实的决策 |
| 2 | 「可达鸭」的命名逻辑（"可达" + "鸭"）是**真实且原创的双关**，品牌价值真实存在 |
| 3 | 改名会**永久损失**产品辨识度，而这个损失无法通过后续工作补回 |
| 4 | 我们的缓解措施（D5 英文名优先、Y1 显著标注、D4 非商业化）**显著降低了实际维权动机** |
| 5 | **但**：若 G-IP1/G-IP2 结论为高风险，本条立即失效，执行 §6 降级 |

> **这是本 ADR 中最需要被复查的决策。** 它的成立完全依赖于 §8 的门禁会被真实执行。若 G-IP1/G-IP2 未完成就上线，方案 B 的否决理由就不再成立。

### 方案 C：擦边改字（「科答鸭」「到达鸭」「可达鸭鸭」）

**描述**：保留原名的大部分字形/读音，只改一两个字，既"规避"又保住传播力。

| # | 否决理由 |
| --- | --- |
| 1 | **法律上无效**：商标近似判断看的是**音、形、义**的整体近似与混淆可能性，改一个字不改变近似性 |
| 2 | 反而可能构成**"明知故犯"的证据**——主动改字表明我们意识到原名的风险 |
| 3 | 品牌上**双输**：既失去了原名的干净双关，又保留了法律风险 |
| 4 | 用户会认为这是"山寨"，损害项目信誉 |

**这是最坏的方案，明确不采用。**

### 方案 D：做周边商品（T 恤、贴纸、钥匙扣）送人或成本价出售

**描述**：校园项目常见的"仪式感"动作。

| # | 否决理由 |
| --- | --- |
| 1 | **实物商品 + 商标性使用**是商标侵权风险最高的场景，正是任天堂维权的主战场（§3.4 的海关查扣案例） |
| 2 | 即使是"成本价"或"赠送"，也可能被认定为商业性使用（尤其有对价时） |
| 3 | 一旦涉及实物，**海关、电商平台、线下执法**等所有维权渠道都会被激活 |
| 4 | 收益（一点仪式感）与风险（侵权）完全不成比例 |

**明确不做**（§4.1 N8）。

### 方案 E：我们自己去申请「可达鸭」或「KedaYa」商标

**描述**：通过申请商标获得自己的权利基础。

| # | 否决理由 |
| --- | --- |
| 1 | 申请「可达鸭」**几乎必然被驳回**（任天堂有在先注册与在先权益），且申请行为本身会**留下记录**，成为"明知"的证据 |
| 2 | 申请「KedaYa」理论上可行，但：① 拼音与「可达鸭」读音相同，仍可能被认定近似；② 我们是非商业项目，**不需要商标来保护商业利益**；③ 申请费用与流程成本对校园项目不划算 |
| 3 | 商标的价值在于排他性，而我们**没有排他的需求**（我们不与任何人竞争市场） |
| 4 | 未来若改名，申请的商标就作废了 |

**结论**：不申请。若未来项目性质变化（如需要保护开源品牌），再评估。

### 方案 F：把风险完全交给用户协议免责

**描述**：在用户协议里写"本项目非官方，名称仅为描述性使用"，靠协议免责。

| # | 否决理由 |
| --- | --- |
| 1 | **用户协议不能对抗第三方的商标权**。协议约束的是用户与我们的关系，不是我们与任天堂的关系 |
| 2 | 免责声明有用（降低混淆可能性），但它是**减轻**措施，不是**免除**措施 |
| 3 | 把它当成唯一防线是危险的自我安慰 |

**结论**：免责声明要做（§4.6），但**不能**作为唯一防线。

### 方案 G：用图形标识替代文字标识（只展示吉祥物，不展示中文名）

**描述**：产品内完全不出现「可达鸭」三个字，只出现原创吉祥物图形。

| # | 否决理由 |
| --- | --- |
| 1 | **不现实**：应用商店/小程序名称必须有文字；用户需要能搜索到我们 |
| 2 | 用户会用中文名口口相传（"那个可达鸭的小程序"），我们无法控制 |
| 3 | 失去中文名的传播力，等于变相改名但没改名 |
| 4 | **但部分采纳**：应用图标用纯图形不含文字（§4.4），这是本条方案中可取的部分 |

**结论**：整体否决，部分采纳（应用图标纯图形）。

### 方案 H：把品牌名做成"运行时完全可配置"，连 `kedaya` 标识都换掉

**描述**：彻底的品牌抽象，任何名字都只是配置。

| # | 否决理由 |
| --- | --- |
| 1 | `kedaya` 是包名（`@kedaya/*`）、DB 前缀、路由路径、仓库名的基础，**换它等于换项目** |
| 2 | 过度抽象会增加无谓的复杂度（契约 §6 的包名是冻结的） |
| 3 | **但部分采纳**：`BRAND.id` 永不变更、`BRAND.displayName` 可配置（§4.5），这已经覆盖了降级所需 |

**结论**：整体否决，部分采纳（§4.5 的可配置化）。

## 10. 后果

### 10.1 正面后果

| # | 后果 |
| --- | --- |
| 1 | 风险被**显式记录**，不再是一个"大家都知道但没人说"的问题 |
| 2 | 吉祥物美术原创性有 checklist 与证据要求，可辩护 |
| 3 | 名称可配置化让"改名"从重构降级为配置操作 |
| 4 | 显著的非官方标注**同时**降低了混淆风险与学校层面的合规风险 |
| 5 | 禁止清单可自动化扫描，不会随时间被遗忘 |
| 6 | 非商业化立场是最强的抗辩理由之一（虽然不能免除侵权认定，但显著降低赔偿与维权动机） |

### 10.2 负面后果（必须承认）

| # | 负面后果 | 严重性 |
| --- | --- | --- |
| 1 | **名称的商标风险无法通过技术手段消除** | **高** |
| 2 | 「kedaya」拼音与「可达鸭」读音相同，**英文名优先的策略并不能消除法律近似性** | 中 |
| 3 | 上线前需要商标检索与法律意见，**有成本且需要时间** | 中 |
| 4 | 若必须改名，应用商店重新审核与用户认知重建的成本**在 M2 后显著上升** | **高** |
| 5 | 显著的免责声明会降低品牌调性（首页 footer 有长声明） | 低 |
| 6 | 吉祥物的差异化约束（§4.3）限制了美术发挥空间 | 低 |
| 7 | 不做周边（N8）会失去一个常见的校园项目"仪式感" | 低 |
| 8 | 舆论上仍可能被指"蹭宝可梦热度"，即使法律上站得住 | 中 |

### 10.3 对工程实践的影响

| 环节 | 影响 |
| --- | --- |
| 品牌文案 | 统一走 `@kedaya/contracts/src/brand.ts` + `copy/brand.ts`，不硬编码 |
| 构建 | 三端都有品牌名构建变量 |
| 资产 | `assets/brand/` 下必须有 `PROVENANCE.md` |
| CI | 新增"禁止清单扫描"任务（文本扫描 + 图片哈希） |
| 上架 | 应用商店描述必须含免责声明；不使用宝可梦关键词 |
| 包名/DB 前缀/路由 | **永不变更**（用 `kedaya`，不用展示名） |
